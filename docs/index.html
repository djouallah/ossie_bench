What is open today

  • The specification and its JSON schema, a validator, and a Python SDK that parses a file. None of them runs a query. validator
  • Compliance cases with expected results, and ost, the tool that runs them. Its view expander turns a query on a model into DuckDB SQL; it reads only the SQL measures, and it is there to test the spec. ost
  • 24 converters that move a model between Ossie and dbt, Cube, Snowflake, Microsoft and others. ossie-converters
  • A reference compiler from Ossie to SQL is on the roadmap. roadmap

About

ossie_bench is not a benchmark. It is an educational repo about semantic modeling, something I care about a lot. One small model, a retailer's daily sales and monthly budget, is written in Apache Ossie and built natively on Power BI, Snowflake, Databricks and BigQuery, then asked the same 15 questions, to see how each one thinks.

How it was built

All the models here were built with AI. I know Power BI well. Every answer is checked against dax-sql's, but any mistake is still mine.

The Ossie file is answered by dax-sql, a toy compiler that N.S. Devaraj started and I work on; it is not a product, and it is not Ossie's.

A personal project

This is a personal project. The views are mine, not my employer's, and nothing here is endorsed by Microsoft, Snowflake, Databricks, Google or the Apache Software Foundation.
